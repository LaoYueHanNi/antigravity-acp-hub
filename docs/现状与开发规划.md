# Antigravity ACP 通用调度插件 · 现状与开发规划

## 一、项目目标

通过标准 **MCP-to-ACP 桥接架构** 与 **MCP Apps 双面板交互**，让 Antigravity 具备以原生子代理体验统一调度所有支持 **Agent Client Protocol (ACP)** 外部 Harness 的能力：

```text
Antigravity (MCP Client + MCP Apps Host)
   ├── 左侧全局页「ACP Hub」(ui://acp-hub/dashboard.html)   ── 配置与诊断
   ├── 右侧扩展栏「ACP 任务台」(ui://acp-hub/task-pane.html) ── 异步派发、流式预览与人工审批
   └──(MCP 工具调用: acp_*)──▶ 本地 MCP Bridge (AcpHub 多连接池 + TaskManager)
                                 ──(ACP JSON-RPC / stdio)──▶ 各 Harness ACP Server
                                                               ├── Claude Code (claude-agent-acp / claude-code-acp)
                                                               ├── Codex CLI (codex-acp)
                                                               ├── Gemini CLI (gemini --acp)
                                                               ├── OpenCode (opencode acp)
                                                               ├── Goose (goose acp)
                                                               └── 其他自定义 ACP Agent
```

> **开源轻量化原则**：核心服务端仅依赖 `@agentclientprotocol/sdk`、`@modelcontextprotocol/sdk` 与 `zod`，不捆绑数百 MB 的厂商私有适配器；通过内置预设自动发现本机 PATH 命令 + 用户级配置覆盖，做到开箱即用且不绑定任何单机环境。

## 二、阶段演进进度

### 阶段 1：Harness 注册表与多进程连接池

- [x] **配置化的 Harness 注册表**（`server/harness-registry.mjs`）：
  - 内置 `claude`、`codex`、`gemini`、`opencode`、`goose` 五大预设的跨平台自动发现链（含 Windows `.cmd`/npm shim 直接解析、60s TTL 解析缓存与可选 `allowNpxFallback`）。
  - 支持 `~/.gemini/config/acp-harnesses.json`（及环境变量 `ACP_HUB_CONFIG`）深度合并、热加载与自定义任意本地命令。
- [x] **多后端 `AcpHub` 连接池**（`server/acp-hub.mjs`、`server/acp-connection.mjs`）：
  - 维护 `Map<harnessId, AcpConnection>` 独立惰性连接池，互不干扰、崩溃自动清理与重建。
  - 采用 `<harnessId>:<nativeSessionId>` 复合会话 ID 自动路由，支持同会话串行锁与跨会话并发。

### 阶段 2：协议能力协商与异构适配

- [x] **`initialize` 能力探测与优雅降级**：
  - 缓存各 Harness 声明的 `agentCapabilities`、`agentInfo` 与 `authMethods`；支持 `acp_list_harnesses(probe=true)` 主动握手诊断。
  - 对不支持 `loadSession`、`session/list`、`additionalDirectories`、`set_mode`、`set_config_option` 的后端提供清晰引导提示或 `warnings`。
- [x] **跨 Harness 通用权限判定**（`server/permission-policy.mjs`）：
  - 以 ACP 标准 `toolCall.kind` 为第一优先级，缺失/`other` 时仅对保守只读/编辑白名单放行，默认 fail-closed。
  - 支持 `read_only`、`interactive`、`accept_edits`、`allow_all`、`reject_all` 五种策略（含内部单轮升级态 `interactive_edits`），并支持提取变更 Diff 预览与涉及文件路径。
- [x] **可选 Client 端 `fs` 与 `terminal` 能力代理**（`server/client-capabilities.mjs`）：
  - 默认对自带工具链的预设关闭，可在 Harness 配置中按需开启；严格受工作区路径白名单（含符号链接防逃逸）与 `approval_policy` 双重约束，会话关闭自动回收终端进程。

### 阶段 3：MCP 工具、零依赖构建与插件规范

- [x] **标准化 `acp_*` 工具集与权限隔离**（`server/index.mjs`、`server/dashboard-resource.mjs`、`server/task-pane-resource.mjs`）：
  - 10 个主模型可见工具：`acp_open_dashboard`、`acp_dispatch_task`、`acp_wait_task`、`acp_list_harnesses`、`acp_new_session`、`acp_prompt`、`acp_load_session`、`acp_list_sessions`、`acp_cancel`、`acp_close_session`。
  - 11 个严格标注 `visibility: ["app"]` 的 `acp_ui_*` 面板控制工具，守住人机交互审批边界。
- [x] **零依赖单文件分发与一键安装**（`server/scripts/build.mjs`、`scripts/install-plugin.mjs`）：
  - 通过 `esbuild` 内联双面板 HTML/JS 与核心协议依赖生成 `dist/mcp-server.mjs`，支持 `agy plugin install https://github.com/LaoYueHanNi/antigravity-acp-hub` 直接零依赖运行。
  - 安装脚本默认采用轻量 `copy` 模式（自动排除 `node_modules` 与 `.git`），亦支持 `--mode symlink` / `--mode junction` 与 `--dry-run`。

### 阶段 4：左配置、右执行双面板与异步任务台

- [x] **左侧全局管理面板「ACP Hub」**（`server/ui/dashboard.html`、`server/ui/dashboard.mjs`）：
  - 可视化展示内置/自定义 Harness 状态、一键启停、设为默认与协议握手探测。
- [x] **右侧扩展栏「ACP 任务台」与异步状态机**（`server/task-manager.mjs`、`server/ui/task-pane.html`、`server/ui/task-pane.mjs`）：
  - 支持异步派发、120s 分段等待与后台守候代理自动唤醒回报；
  - 块级增量 Markdown 渲染 + 思考过程贴底流式预览 + 单卡限高展开收起 + 自动隐身极细滚动条；
  - 吸顶任务计划与涉及文件点击直达 Antigravity 侧栏源码预览；
  - 置顶交互式审批卡片（180s 超时 Fail-Closed）、右侧多轮直接追问、一键回报主对话/附为下条上下文；
  - 任务历史原子持久化至 `~/.gemini/config/acp-tasks.json`，支持宿主重启自动恢复并通过 `loadSession` 断点续聊。
- [x] **自动化测试与决策记录体系**：
  - 19 项自动化单测与端到端测试全通过（覆盖异步派发、交互审批放行/升级/拒绝/超时/取消、持久化重启续聊、App-Only 隔离与无 `node_modules` 隔离启动验证）。
  - 建立 `docs/decisions/` 架构决策记录体系与零依赖校验脚本 `docs/decisions/check.mjs`。
