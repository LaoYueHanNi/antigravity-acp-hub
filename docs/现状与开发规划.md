# Antigravity ACP 通用调度插件 · 现状与开发规划

## 一、项目目标

通过标准 **MCP-to-ACP 桥接架构**，让 Antigravity 具备统一调度所有支持 **Agent Client Protocol (ACP)** 的外部 Harness 的能力：

```text
Antigravity (MCP Client)
   ──(MCP 工具调用: acp_*)──▶ 本地 MCP Bridge (AcpHub 多连接池)
                                ──(ACP JSON-RPC / stdio)──▶ 各 Harness ACP Server
                                                              ├── Claude Code (claude-agent-acp / claude-code-acp)
                                                              ├── Codex CLI (codex-acp)
                                                              ├── Gemini CLI (gemini --acp)
                                                              ├── OpenCode (opencode acp)
                                                              ├── Goose (goose acp)
                                                              └── 其他自定义 ACP Agent
```

> **开源轻量化原则**：核心服务端仅依赖 `@agentclientprotocol/sdk`、`@modelcontextprotocol/sdk` 与 `zod`，不捆绑数百 MB 的厂商私有适配器；通过内置预设自动发现本机 PATH 命令 + 用户级配置覆盖，做到开箱即用且不绑定任何单机环境。

## 二、阶段演进进度

### 阶段 1：Harness 注册表与多进程连接池

- [x] **配置化的 Harness 注册表**（`server/harness-registry.mjs`）：
  - 内置 `claude`、`codex`、`gemini`、`opencode`、`goose` 五大预设的跨平台自动发现链（含 Windows `.cmd`/npm shim 直接解析与可选 `allowNpxFallback`）。
  - 支持 `~/.gemini/config/acp-harnesses.json`（及环境变量 `ACP_HUB_CONFIG`）深度合并、热加载与自定义任意本地命令。
- [x] **多后端 `AcpHub` 连接池**（`server/acp-hub.mjs`、`server/acp-connection.mjs`）：
  - 维护 `Map<harnessId, AcpConnection>` 独立惰性连接池，互不干扰、崩溃自动清理与重建。
  - 采用 `<harnessId>:<nativeSessionId>` 复合会话 ID 自动路由，支持同会话串行锁与跨会话并发。

### 阶段 2：协议能力协商与异构适配

- [x] **`initialize` 能力探测与优雅降级**：
  - 缓存各 Harness 声明的 `agentCapabilities`、`agentInfo` 与 `authMethods`；支持 `acp_list_harnesses(probe=true)` 主动握手诊断。
  - 对不支持 `loadSession`、`session/list`、`additionalDirectories`、`set_mode`、`set_config_option` 的后端提供清晰引导提示或 `warnings`。
- [x] **跨 Harness 通用权限判定**（`server/permission-policy.mjs`）：
  - 以 ACP 标准 `toolCall.kind` 为第一优先级，缺失/`other` 时仅对保守只读/编辑白名单放行，默认 fail-closed。
  - `accept_edits` 放行只读与 `edit`，仍拦截 `delete`、`move` 与 `execute` 交由用户确认；`allow_all` 优先选 `allow_once` 防止跨轮次授权污染。
- [x] **可选 Client 端 `fs` 与 `terminal` 能力代理**（`server/client-capabilities.mjs`）：
  - 默认对自带工具链的预设关闭，可在 Harness 配置中按需开启；严格受工作区路径白名单（含符号链接防逃逸）与 `approval_policy` 双重约束，会话关闭自动回收终端进程。

### 阶段 3：MCP 工具与插件规范通用化

- [x] **重构为 7 个通用 `acp_*` 工具**（`server/index.mjs`）：
  - `acp_list_harnesses`、`acp_new_session`、`acp_prompt`、`acp_load_session`、`acp_list_sessions`、`acp_cancel`、`acp_close_session`。
  - 去除 Claude 专属硬编码参数，采用自由字符串 `mode`、`model` 与通用键值 `config_options`。
- [x] **更新插件清单与通用技能**：
  - 按 Antigravity 官方发布规范更新 `plugin.json`（`name: "acp-hub"`、`displayName: "ACP Hub for Antigravity"`、`$schema`、`logo: "assets/logo.svg"`）与 `mcp_config.json`（使用 `${PLUGIN_ROOT}/dist/mcp-server.mjs`）。
  - 通过 `esbuild` 构建零依赖自包含产物 `dist/mcp-server.mjs`，支持 `agy plugin install <GitHub URL>` 或 Marketplace 安装后免 `npm install` 直接运行。
  - 重写 `skills/acp-hub/SKILL.md` 多 Harness 协同与安全调度指南。

### 阶段 4：自动化测试与一键安装发布

- [x] **补齐自动化测试与真实冒烟测试**（`server/test/mock-acp-agent.mjs`、`server/test/acp-hub.test.mjs`、`server/test/smoke-real-harness.mjs`）：
